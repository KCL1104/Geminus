The S3-compatible object storage adapter (`internal/storage/objects/s3.go`, ADR-029) brings in no module: SigV4 signing is implemented with the standard library and verified with the SigV4 test suite AWS publishes (`testdata/sigv4`, Apache-2.0, THIRD_PARTY_NOTICES). When a base image is upgraded, update the digest, this table and the files `scripts/check_deploy.py` checks.

Per ADR-001 the HTTP layer uses `net/http` and brings in no web framework. SQL generation (sqlc/explicit SQL), frontend state/UI libraries, auth, cloud and object storage are still TBD; this ADR does not choose them. The LLM provider was set to Anthropic by H-001, but the SDK (`github.com/anthropics/anthropic-sdk-go`) version is left for T-024 to choose. T-024 (2026-10-19, ADR-027 ACCEPTED, H-019): `github.com/anthropics/anthropic-sdk-go` **v1.78.0** (released 2026-09-30, over two weeks; v1.79.0/v1.79.1/v1.80.0 were released 2026-10-07 to 09, under two weeks), MIT; pinned in `go.mod`/`go.sum`. Only `internal/ai/provider/anthropic` links it (architecture rule `llm-sdks-only-in-ai`); the modules it brings along and their licenses are listed in [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md). It has not been used to call the real API yet (live AI awaits the owner's approval of the model, quota and data policy, H-017). **Accepted transitive pre-release** (T-024 review L7): through `github.com/pb33f/ordered-map/v2` v2.3.1 (its `yaml.go`), the SDK brings in `go.yaml.in/yaml/v4` **v4.0.0-rc.2** (released 2025-08-28, pinned in `go.sum`). This is a release candidate, not a stable version; the dependency graph of SDK v1.78.0 offers no choice without it, so it is accepted. Risk: the rc's API and parsing behaviour may change before the final release, and security fixes may only appear in later versions; this module does no YAML encoding or decoding (the adapter's requests/responses are all JSON), so it is code that is linked but not called. Recheck this dependency when the SDK is upgraded, and upgrade `go.yaml.in/yaml/v4` once a final release exists.

## Consequences

- `make backend-*` covers only `./cmd/... ./internal/...`, so that Go files shipped inside npm packages are not treated as part of this module. Adding a new top-level Go directory requires updating `GO_PKGS`.
- `next build` rewrites `tsconfig.json` (adding `esModuleInterop`, `.next/dev/types`); the rewritten content is committed so that the build does not dirty the working tree.
- `npm audit` (including dev) shows 5 high, all of them `braces` GHSA-vfj7-8cjw-p6xm on the dev-only lint chain, with no patched version yet; production dependencies show 0. On 2026-10-15 the owner accepted this dev-only risk (D-031); CI's frontend job blocks high/critical advisories in production dependencies with `npm audit --omit=dev --audit-level=high`, and upgrades once upstream has a fix.
- A version upgrade must update this ADR and the lockfile, and rerun `make spec-check backend-test backend-race frontend-test frontend-build`.
