# ADR-027 — AI provider adapter and sanitized context (T-024)

Status: ACCEPTED (2026-10-20, owner H-019: 「Q2 選 B，其他照建議」 ("Q2: choose B; the rest as recommended"); proposed and implemented by the T-024 agent on 2026-10-19, passed independent review). Basis: H-001, H-017, D-002, D-016, D-018, D-046 (all APPROVED), AI_SPEC §2–§4, §9–§10, SECURITY §7, AGENTS.md §2. This ADR approves no live AI call: the model, the token quota and the data policy are still for the owner (H-001, H-017).

## Context

T-024 delivers the provider interface (three explicit modes: fake/disabled/live), a tenant-safe context builder (minimal context, bounded summary, credential redaction, a cross-tenant hard filter, UNTRUSTED_DATA kept apart from the system rules, visible omissions, the D-046 ID pool), token/timeout/retry budgets, the provider schema projection, and `output_locale`. H-001 names the Anthropic Claude API; D-018 decides that the keys of two independent organizations are used with an ordered primary→secondary failover; H-017 names the variables `GEMINUS_ANTHROPIC_API_KEY_A`/`_B` and states that the environment holds no key and the live AI gate is unchanged.

## Decision

### Packages and boundaries

| Package | Contents | Dependency limits (`scripts/check-architecture`) |
|---|---|---|
| `internal/ai/provider` | `LLMProvider` (the three methods of AI_SPEC §2), the sealed `Prompt`, `Client` (the checks all modes share), `Backend`, `Disabled`, typed `Error`, `Budget`, the provider output types | `ai-suggests-only`: must not depend on any application layer (storage, tenant, models, runs, worker, httpapi, api, auth, config, packs…), a DB driver, `database/sql` or `os/exec`; `ai-is-pure-but-the-adapter`: no network, DB, process I/O or LLM SDK; the standard library it imports itself may only be the kernel's computational allowlist, and third-party packages only the kernel's allowlist |
| `internal/ai/provider/fake` | deterministic fake backend | same as above |
| `internal/ai/provider/anthropic` | live backend (the official Go SDK) and the schema projection | `ai-suggests-only`; the only package that may depend on an LLM SDK (`llm-sdks-only-in-ai` now exempts only it and cmd). A package that depends on it also depends on the SDK, so only the composition root (cmd) can assemble the live backend |
| `internal/ai/aicontext` | context builder (proposal, analysis, mapping) | same as provider |
| `internal/ai/idpool` | D-046 pool generation, shape check, candidate check | same as provider |
| `internal/ai/locale` | `output_locale` validation and the provider instruction, the prose number check | same as provider |
| `internal/ai/corpus` | the fake-provider corpus tests of `make ai-eval` (tests only) | same as provider |
| `prompts` (`prompts/embed.go`) | embeds the versioned system prompts | — |
| `internal/secret` | `Secret`: every fmt verb, JSON and slog print `[redacted]` | — |

The `internal/ai/context/` planned in tasks.json is renamed `internal/ai/aicontext` (`context` would shadow the standard library's package name).

### Modes and settings (`internal/config`, `LoadAI`)

- `AI_PROVIDER` unset or `disabled`: every AI call returns `provider_not_configured` (mapped to `AI_PROVIDER_NOT_CONFIGURED` at the HTTP layer, T-025).
- `fake`: accepted only when `APP_ENV` is development/test (in production or unset, startup is refused), the same as the D-044 filesystem adapter.
- `anthropic` without `AI_POLICY_APPROVAL`: accepted, but every AI call returns `policy_not_approved` (`AI_POLICY_NOT_APPROVED`), and **no key is read**.
- `AI_POLICY_APPROVAL` must be an owner approval listed in this build (the register in `internal/config/aiapproval`, currently empty); otherwise startup is refused (`not_approved`). An approval is an `aiapproval.Approval` token: only `aiapproval.Recorded` can produce one from the register (the zero value is invalid, `Valid` re-checks the register each time); the config's `AI.Approval` and the live adapter's `Config.Approval` are both this type, and the adapter's `New` rejects an invalid token (review L5). This leaf package is the only part of `internal/config` the adapter may import (the allow of `ai-suggests-only`); only tests in its own directory can register an approval temporarily (`export_test.go`). Adding an entry is the owner's decision (model, token quota, data policy, matching retention/ZDR of the two organizations, D-018), a change written into DECISIONS_AND_TBD and reviewed; agents do not add one. So the default settings, and even any combination of environment variables, cannot enable live AI.
- Only after the approval are `AI_MODEL` (required, no default: the TBD "LLM model" is chosen by the owner after the eval), `GEMINUS_ANTHROPIC_API_KEY_A` (primary, required, label `org-a`) and `_B` (secondary, optional, label `org-b`) read. `AI_API_KEY` is always refused (the old name). `ANTHROPIC_API_KEY` is never read.
- Budgets: `AI_MAX_PROMPT_BYTES`, `AI_MAX_OUTPUT_TOKENS`, `AI_TIMEOUT_SECONDS`, `AI_ATTEMPT_TIMEOUT_SECONDS`, `AI_MAX_RETRIES`, `AI_MAX_CONCURRENT_PER_ORGANIZATION` override the defaults; `provider.BudgetCaps` checks the caps.

### Client (every mode goes through it)

In order: the caller's context has ended → `cancelled`; disabled → its code; the organization ID format, the prompt's role matching the mode, the prompt sealed and unchanged (`InputHash` recomputed) → otherwise `invalid_request`; prompt bytes ≤ `MaxPromptBytes` (each tokenizer token is at least one byte, so this is also an upper bound on input tokens) → otherwise `context_too_large`; concurrent calls of the same organization in this process < `MaxConcurrentPerOrganization` → otherwise `concurrency_limited` (no waiting); `Timeout` wraps the whole call (all retries and failover). The answer must be non-empty, ≤ `MaxOutputBytes`, one JSON document (no duplicate member, invalid UTF-8 or trailing data) and pass the role's full 2020-12 output schema, otherwise `invalid_output`: the error carries only the issue's JSON Pointer and a fixed message, never any text of the answer (AI_SPEC §4). Schema-valid is not authorized: the proposal's semantic validation, risk and pool check belong to T-025.

Budget defaults (engineering candidates like D-007, adjustable after the benchmark and the owner's quota decision): prompt 128 KiB (cap 512 KiB), output 8192 tokens (cap 32000), output 256 KiB, the whole call 120 s (cap 300 s, the D-007 job timeout), each attempt 90 s, 2 retries (cap 4), 2 concurrent per organization (cap 16). There is **no** token quota accumulated per tenant and period: that needs persistence and the owner's quota numbers (H-001, H-017), and belongs to T-025/T-036.

### Context builder (`aicontext`)

- **Cross-tenant hard filter**: every input carries its organization (and model): base version, ID pool, data summary, run result, import. If any one is outside the request's scope, the whole build fails (`cross_tenant_input`, with a JSON Pointer); no partial context is returned. A run result's run ID must be that run's; only completed runs are analysed.
- **System rules hold only trusted text**: the versioned template (`prompts/<role>/system.md`), the fixed server rules (`context-rules-3`: the `output_locale` instruction now says structured fields copy units verbatim, while prose numbers may be rounded, ratios may be written as percentages with %, and units are written in the output language (the T-030 live analysis of 2026-10-28 copied `497.4225096419336 minute` verbatim); -2 is -1 plus "prose does not write block names", after the assumptions of the T-057 live demo showed `CURRENT_MODEL_IR` and `USER_INTENT`), the mode rules (the pool rules of edit, the D-021 allowlist of scenario), the domain pack's static `PromptContext` (domain-neutral: the builder contains no domain vocabulary. `TestNoDomainVocabulary` checks that no string literal of the builder, and none of the rules it produces for the four roles with the neutral pack (versioned templates included), contains the vocabulary of either domain — the software delivery example pack and the electronics line of docs/domains/ELECTRONICS_LINE.md; the only exceptions are the contract's own member names: `Result.metrics.dora` (CB-37) and the canonical event's `deployment_id` target field. T-024 review L7 therefore made the DORA/deployment wording of the analyst and importer templates neutral, versions analyst-0.3.1 and importer-0.2.1), and the fixed instruction of `output_locale`.
- **The user message holds only blocks**: `<server_data name="…">` (ID_ALLOCATION_POOL, ALLOWED_METRIC_REFERENCES, CONTEXT_OMISSIONS) and `<untrusted_data name="…">` (model IR, entity index, intent, question, selected IDs, data summary, results, columns, sample rows). Each block's content is one JSON value; `Seal` re-encodes it and escapes `<`, `>`, `&`, U+2028 and U+2029, so data cannot close its own block or forge another; `Seal` also rejects system rules that contain a block. `InputHash` = JCS + SHA-256 (organization, role, template version, locale, system, user), the sanitized input hash of the audit. The organization goes only into the hash and is not sent to the provider; `Seal` requires it to be a D-001 organization ID, and `Client` rejects a prompt whose organization differs from the call's (review L6).
- **Redaction (default deny)**: every untrusted string and member name: PEM and PGP private key blocks, long mixed-case-and-digit base64 (a key body, token or signature standing alone: at least 40 characters and containing `+`, `/` or `=`, or at least 64 characters; a single-case hex digest does not count; the base IR's own entity IDs and references to them do not count however long they are, re-review L-new), `sk-ant-`/`sk-`/`pk-`/`rk-` keys, Stripe (`sk_live_`…), AWS, GitHub, GitLab (`glpat-`), Slack, Google keys, JWTs, bearer/basic tokens, key=value/key: value whose key ends in a complete credential word (preceded by any segments separated by `_`, `.` or `-`: `DB_PASSWORD=`, `aws_secret_access_key =`, `?access_token=`, `GITHUB_TOKEN=`, `AccountKey=`, `spring.datasource.password=`; token counts only alone or after a credential qualifier such as access, refresh or github; `tokenizer:`, `secretary:`, `max_tokens:`, `token_bucket_rate:`, `rate_token:` do not count; the value runs to whitespace or `, ; " ' &`), any URL (including `www.…` without a scheme and `host.tld/…` with a path; a file name without a path such as `steps.csv` does not count), e-mail, IPv4, D-001 server IDs (uppercase ULID; the pool's lowercase IDs are not affected), invisible control/format characters (bidi override, zero-width, BOM). Each is marked `[REDACTED:<kind>]` and counted. When a member or import column name looks like a credential (after splitting into words, the last word is password, passphrase, secret, credential(s) or authorization, or the last two words are API/access/account/private/secret key or connection string, or it is a lone token, or token after a credential qualifier; it does not count when the credential word is not last, as in `secret_stage`, `pwd_station`, `credentials_required`, `rate_token`, re-review L-new), the whole value is replaced by `[REDACTED:credential]` whatever it looks like (except null and boolean). Cookies are not on the list: no Go code may contain a cookie header name (`TestNoGoCodeHandlesCookies` in `internal/auth`, ADR-018 BFF); a session cookie's value, if it is long base64, is still masked by the rules above. Characters that look like angle brackets (full-width, small, CJK, mathematical and technical angle brackets, single guillemets, modifier arrowheads) are turned into ASCII and counted as `delimiter`, then escaped by `Seal`; 《》 and 「」 are Chinese punctuation and are left unchanged. When two member names become equal after redaction, the first is kept (by name order; import rows by column order) and the rest are listed in CONTEXT_OMISSIONS (`members`, `redaction_collision`). (T-024 review M2, L3, L4) Known limits: long mixed-case identifiers of 64 characters or more that are not model IDs are still masked; in free text, a key joined to other words in camelCase (`dbPassword=`) is not recognised by the key=value rule (JSON member and import column names are split into words at case changes); there is no IPv6 rule.
- **Bounded and minimal**: strings 2000 characters (intent 20000, question 10000, names 200, cells 200); root metadata ≤ 2 KiB, a node's domain_attributes ≤ 1 KiB; data summary ≤ 8 KiB; sample rows ≤ 20; columns ≤ 256; no model ID, version ID, run ID, hash, views, replication summaries or dataset version ID is sent.
- **Visible omissions**: CONTEXT_OMISSIONS and the prompt's `Disclosure` list the kinds omitted, their counts and a fixed reason code (no values). Over budget, in order: drop metadata/domain attributes/data summaries → show only the neighbourhood of the selected entities in full, with other entities holding their original index as `{"id","omitted":"budget"}` (the JSON Patch path indexes do not change) → send no IR; ENTITY_INDEX always lists every entity and its real index. When the minimal context is still over budget, the answer is `context_too_large`; there is no silent truncation.
- **D-046**: the edit mode's context carries the proposal's pool (server_data); scenario does not (a scenario adds no entity). The pool must belong to the scope, have the right shape and contain no ID the base already uses.

### `output_locale`

`locale.Parse`: empty is `en`; otherwise it must equal `en` or `zh-Hant` exactly, and the error points to `/output_locale` without quoting the client's value. The instruction is fixed server text per locale: prose in that language; IDs, JSON Patch paths, JSON Pointers, member names, enums, reason/error codes, metric paths and units always copied verbatim; numbers always in Arabic numerals. `locale.CheckProse` finds the numbers in prose that cannot be checked: Arabic numbers that match no supplied value (rounded to the displayed decimals, or as a percentage), number words (Chinese numeral strings, 百分之 ("percent"), a numeral plus a classifier or unit; English two…trillion, dozen, twice, half; article uses such as 「一個」 ("one", general classifier), 「一台」 ("one", machine classifier) and "one" do not count) and non-ASCII digits. The analysis context returns the supplied numbers (results, comparison, config, capacities and probabilities, not array indexes) and the metrics that may be cited (only available ones); wiring it into the analysis's completed/failed is T-030.

### Live adapter (`anthropic`)

- The official SDK `github.com/anthropics/anthropic-sdk-go` **v1.78.0** (released 2026-09-30, two weeks old; v1.79.x/v1.80.0 were less than two weeks old), MIT; the transitive modules and their licenses are in THIRD_PARTY_NOTICES.
- `NewClient` is not used: its default chain reads `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_CUSTOM_HEADERS`, the SDK profile and workload identity. Each credential gets one `NewMessageService` carrying only an explicit base URL, HTTP client, key, retry count and attempt timeout. The base URL is the constant `https://api.anthropic.com/`; only tests (`export_test.go`) can change it. The HTTP client does not follow redirects (otherwise the key header would follow).
- D-018: credentials are tried in order; only 401, 402 and 403 mark one unavailable and move to the next: 401/403 (key invalid or revoked) until the process restarts (a key change restarts it), 402 (credits used up) rests 15 minutes (`billingCooldown`) and then is tried again, because credits may be topped up (the choice from review INFO; only 402 is probed again, since 401/403 do not become valid with time); a skipped credential is listed in `failed_over_from` on every later call, so the audit shows each call that did not use the primary; 408, 409, 429, 5xx (529 included) and connection errors are retried on the same credential with the SDK's backoff up to the budgeted count and then fail (`rate_limited`/`unavailable`, retryable), without switching organization; other 4xx are `request_rejected`, with no retry and no switch. All refused is `credentials_exhausted`. Responses, metadata and errors carry only the label.
- Request: the approved model, `max_tokens`, one system text block, one user text block, `output_config.format` set to the projected schema. No tools, tool_choice, thinking settings, sampling parameters or metadata. Stop reason: `end_turn`/`stop_sequence` take the text block (thinking blocks are discarded, not stored), `max_tokens` → `output_truncated`, `refusal` → `refused`, anything else (tool_use and pause_turn included) and any tool block → `invalid_output`.
- **Schema projection**: resolve `$ref` (recursion is rejected), turn `oneOf` into `anyOf` (each output schema's branches are told apart by a const member, so both allow the same values), remove the constraints the subset does not support (lengths, numeric bounds, pattern, array bounds, uniqueItems, if/then/else, not, unsupported formats) and list them in `Dropped`; reject open objects, `patternProperties` and other keywords that cannot be projected without loosening. Constraints are only loosened, no member is added and no object is opened; the server checks every answer against the full schema. (Note added 2026-10-26, T-053 live smoke: the only exception is the places in the canonical schema that accept any JSON value (the JSON Patch `value`); the API rejects an empty schema, so they are projected as a JSON text string and listed in `Encoded`, and the adapter strictly decodes these places before the full schema validation; the rule and the reasons are in AI_SPEC §2.)

## Consequences

- Every mode goes through the same `Client`; fake answers must also pass the full schema; E2E (T-040) is driven by the fake's script.
- The live adapter has been tested only against a local httptest server. Any call to the real API, whether the API accepts the projected schema, and how `output_config` behaves on the model the owner chooses: **NOT RUN**. (Note added 2026-10-26, T-053: the first live smoke was refused with 400 because of an empty projected schema; the coordinator confirmed with the free `count_tokens` that the corrected projection is accepted (HTTP 200, input_tokens 1682); the model's actual answer under `output_config` is still NOT RUN. See AI_SPEC §2, checks/T-053_VALIDATION.md.)
- A credential marked unavailable by 401/403 is not used again until the process restarts (a key change restarts it); a 402 credential is tried again after 15 minutes, and rests another 15 minutes if it is still 402. The cooldown is per process; several workers each probe on their own.
- The SDK reads the whole response body before the client's `MaxOutputBytes` check; the body's size is limited by `max_tokens` and the attempt timeout, not by that check.
- `locale.CheckProse` ignores the sign when it compares numbers (「減少 3.5」 ("decreased by 3.5") matches -3.5); whether the direction of a delta is right is for the T-030 analyst check.
- The choice of minimal context: when the IR fits the budget, the full IR is sent (minus the server-bound IDs and views), because a patch's JSON Pointer indexes and references need the whole topology; only over budget is it reduced in order (see Context builder).
- The concurrency limit is per process; several workers multiply it. A period quota, prompt caching (data retention is a data-policy matter) and refusal fallback to another model (changing model is for the owner) are not done.
- Among the transitive modules is `go.yaml.in/yaml/v4` v4.0.0-rc.2 (a release candidate released 2025-08-28): pulled in by `yaml.go` of `github.com/pb33f/ordered-map/v2` (both the SDK and invopop/jsonschema import ordered-map), not by the SDK's profile settings; neither this module nor the adapter's paths encode or decode YAML. ADR-011 records it as an accepted transitive pre-release and its risk.

## Alternatives

- A hand-written HTTP client: the task instructions allow only the official SDK or a NOT IMPLEMENTED stub.
- Structured output through a forced tool: new models refuse a forced `tool_choice`, and "no mutation tool" is easier to audit; `output_config.format` is chosen.
- Failover on 429 too: it would in effect merge the two organizations' rate limits; D-018 does not adopt it.

## Addendum (T-055, 2026-10-26, PROPOSED)

The second live adapter (Meta Model API) is in [ADR-030](ADR-030-meta-model-api-adapter.md) (PROPOSED). What this changes in this ADR (the ACCEPTED parts are unchanged; the items below await independent review):

- The schema projection and the decoding of open values move from `internal/ai/provider/anthropic` to the shared `internal/ai/provider/structured` (only the package name changes; `anthropic.Project` and the constants become aliases of it, and anthropic's tests are unchanged).
- `anthropic.New` also rejects an approval whose provider is not `anthropic` (`Approval.Provider()`), and `meta.New` one that is not `meta`; the architecture rule `live-adapters-apart` forbids the two adapters to link each other.
- `provider.Prompt` can carry images (`Images`, counted in the prompt hash); `Client` passes them only to a backend that implements `provider.ImageInput` and accepts images; the Claude adapter does not implement it, so a prompt with images is `invalid_request` before it reaches it.
- `provider.Segmenter`/`SegmentClient` is the second kind of client, for the photo path (SAM 3.1); metering, budgets and error codes are the same as `Client`'s.
- Spend: only a `spend.GeoPriced` model (`claude-opus-5-5`) multiplies its reservation by 1.1 and settles by geo; other models (Muse Spark) use the list price.
- The API's availability reads no key (T-053 I5; the T-055 follow-up, 2026-10-26, **the coordinator's decision**, PROPOSED until independent review): the API no longer goes through `LoadAI`; with `config.LoadAPI`/`LoadAPIAI` it decides from `AI_PROVIDER`, `AI_POLICY_APPROVAL`, `AI_MODEL` and `GEMINUS_AI_LIVE` whether it accepts proposals; the check is the worker's live gate (`liveGate`, the same code) but it neither reads nor requires a key; when they do not match, startup is refused with the switch on, and `policy_not_approved` is returned with it off; if the API's environment holds any AI key variable, startup is refused (`key_forbidden`). The worker and the live adapters are unchanged. See SECURITY §7 "The API's key-free availability" and runbook §4.4. The photo path's settings (`AI_VISION_PROVIDER`, `AI_VISION_POLICY_APPROVAL`, `AI_VISION_MODEL`) are also added (the T-056 follow-up, the coordinator's decision, PROPOSED): the worker and the API share `config.decide` (the worker with `loadLive`, which reads keys, the API with `keyFree`, which does not); with the photo path off, `createImageProposal` returns 503 (`details[0].code` `AI_IMAGE_UNSUPPORTED`).
