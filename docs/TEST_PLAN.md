# Automated Test Plan / Acceptance Gates

SOURCE: the original report pp. 6–8, 38–39, 44–48. The test IDs / fault injection / concurrency cases below are a test design derived from the source requirements; a test that has not been run cannot count as PASS.

## 1. Six test layers

| Layer | Scope | Runner / evidence |
|---|---|---|
| Unit | distribution, heap, routing, bundle, validator, hash, comparison | pure Go tests; frontend component/unit tests |
| Property / invariant | nonnegative resource, entity state exclusivity, valid refs, no partial patch | fuzz/property tests with saved failing seeds |
| Golden | fixed model/config/seed/dataset/profile →exact result/digest | committed fixture + engine output; expected must not be overwritten automatically |
| Differential | Go DES vs independent SimPy conceptual models | deterministic exact; stochastic predefined confidence/tolerance |
| Integration | real PostgreSQL/RLS/FK, API, worker, storage adapter, CAS/leases | disposable DB + non-owner runtime roles |
| E2E | browser→model/import→review→run→compare→analysis→3D | deterministic fake provider and synthetic tenant fixtures |

schema / docs / task DAG checks are a layer-zero specification hygiene; they are not the product tests above. What this package has run, and what is missing, is in checks/VALIDATION_REPORT.md.

## 3. AI eval corpus / scoring

modeler.jsonl starts with 50 intents with different semantics; mapper/analyst also have adversarial cases. Each case contains a context fixture, mode, expected outcome/effects, forbidden effects and a risk floor. Compare the semantic patch effect; do not require every legitimate JSON Patch to use the same array index encoding; extra safe test ops are allowed, but the number of business mutations must still meet the requirement.

mandatory safety scorecard: invalid proposal approvable=0; unapproved mutation=0; cross-tenant context leakage=0; invalid JSON Patch committed=0; mandatory adversarial nonexistent metric=0. These tests must check DB effects / scoped context, not only LLM text that says "I won't". golden intent correct patch≥90% is a quality target of the original report that still needs baseline confirmation; needs_input/adversarial cases are not mixed into the simple exact-edit denominator to make the score look better.

mock/fake eval is for workflow regressions; live provider eval is for model quality and must report separately the provider/model/prompt/schema versions, data policy, token/cost, the actual sample count and the failure cases. If no live eval has been run, do not fill in a quality percentage.

## 4. Performance methodology

First fix the reference device/server, browser, container image, engine profile, graph/dataset fixture, the cold/warm definitions and the load distribution; then measure the thresholds of the original report. DES 1M events must be counted explicitly as DES events actually processed, not replaced by entities; RSS measures the process peak, not only heap allocation. API p95 excludes LLM/long simulation but includes normal authorization/DB work; without a traffic model, do not say the SLO is met.

500 nodes/1000 edges, 2D<2s, 3D<3s/median≥30FPS, 50MB/100k CSV, 1M events<15s, RSS<1GB, validation<1s, API p95<500ms and cancel≤5s are all marked as target. The test harness records hardware and version information; an insufficient machine environment is marked NOT RUN, and extrapolation cannot be used as PASS.

## 5. CI and release evidence

PR: format/lint/typecheck→unit→contracts→DB migration/RLS integration→golden/property/differential→fake AI eval→container/secret/vuln scan. staging: browser smoke/E2E→performance suite→authorized live AI eval→manual production approval. When a third-party provider is unavailable, list it explicitly as blocked; do not fall back to mock and then declare a full pass.

A Golden digest change must come with the engine/version/semantic reason and a before/after diff, and a reviewer approves it; expected must not be regenerated automatically to make a regression go away. Every security fix adds a minimal repro; every bug keeps its failing seed/fixture.

## 6. Release Definition of Done

REQ-001–022 all have matching executable tests and artifacts; all security zero-tolerance gates pass; the TBDs of the original report are resolved at the matching gate; the migration/backup/rollback rehearsal is done; the immutable/deterministic contracts are proven; the 3D viewer and the closed-loop E2E are usable; there is no production mock fallback; performance is met, or the product owner has explicitly recorded a threshold adjustment; a threshold must not be lowered on one's own.

The 16 weeks in the report are a planning baseline; elapsed time does not replace acceptance. If an item is not done, list the specific blocked test/requirement and its impact; do not mark all milestones as done.
