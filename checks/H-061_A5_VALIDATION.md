## 2. Findings and decisions taken in the slice

1. **A1's probes are not run, so the digest is the default.** H-061 says "the results choose replay or digest for A5". With P1-P5 NOT RUN, `ParseTranscriptMode("")` is `digest`, which needs only the single-turn `tool_use` verified live for both models (H-060). Replay is built, tested against the fake and a local test server, and selectable with `INVESTIGATOR_TRANSCRIPT=replay` once P1 passes. `tool_choice` any (P2) is sent on every planner turn although P2 is NOT RUN: Meta's Messages page lists `any`, and a refusal of it would show in A9's first live turn as a typed error, not a wrong call. `strict: true` (P4) is not sent.
2. **One tool pipeline.** `PlanTurn` is a policy over `Client.call`'s tool turn (E1 finding 1, PROPOSED there): the investigator role's turns can only go through it (`Client.Turn` refuses the role), so the one-attempt, one-call, strict-decode and note rules cannot be skipped by another caller. A6's `einomodel.Planner` should call `PlanTurn`, not `Metered`'s `Call.Turn`.
3. **Tool schemas are projections; the bounds stay server-side.** E1 finding 5 (Meta's `SchemaViolations` refuses `minLength`, `pattern`, `minimum` …) is resolved in the registry: the input schema the model is sent keeps types, members and enums only, so it passes Meta's documented limits and the client's closed-schema check, and every bound and pattern is checked by the decoder (`Decode`: the full 2020-12 schema, NFC) on every call. Each projection takes every valid argument fixture and refuses an unknown member (test).
4. **The note is not normalized to NFC.** `internal/ai/provider` links no Unicode tables (`aigraph-has-no-storage` and the photo pipeline's rule would refuse them); the note has no NFC rule in the schema. Invalid bytes become U+FFFD, which the eval counts as garbled.
5. **The context builder does not link the registry; one architecture rule follows the merge.** A first build had `aicontext` import `internal/ai/investigator` (for its types); the full architecture tests then refused it (`TestEinoAgreedPlacementsConform`: the planned role graphs `internal/aigraph/proposal` and `analysis` link `aicontext`, and would have linked the registry's `golang.org/x/text/unicode/norm`, which `aigraph-has-no-storage` refuses). So `aicontext` takes plain values (`InvestigationStep`, `InvestigationBudget`, the mode as a string), a parity test holds its constants and budget shape to the registry's, and the caller maps its ledger mirror (`aievals.BriefSteps`; A6 likewise). Separately, merging A2 into the main branch had left `TestPhotopipelineRuleKeepsTheAIPackagesLists` failing (A2 widened `ai-is-pure-but-the-adapter` to `aiThirdParty`; E0's test requires the photo pipeline's rule to keep the same lists): the photo pipeline's rule now takes `aiThirdParty`, as its comment and that test say it must. A6 will need `aigraph-has-no-storage` to take `norm` and `transform` once `internal/aigraph/investigator` links the registry (PROPOSED).
6. **Invalid kinds.** Beyond §7's list: two calls are `several_calls` (a refused `invalid_call` step, `INVALID_ARGUMENTS` at ""); a call ID not of a token's shape is `invalid_arguments` at ""; a refusal stop, an answer the backend could not take, another model's answer or an unoffered web search are `no_call` (unrecorded); narration that is not UTF-8 or over the output budget is `invalid_text` (unrecorded); a decoder `INTERNAL` is the server's fault, `invalid_request`, not an invalid turn. Every `invalid_output`, `output_truncated` or `refused` error of `PlanTurn` carries `Invalid` (tested), so A6 needs one rule.
7. **Prompt size.** The brief (at most 64 KiB) plus a 14-step digest (at most 112 KiB) can exceed the default `MaxPromptBytes` (128 KiB). The live eval raises it to 256 KiB for the planner only (within `BudgetCaps`); A6's separate investigator client needs the same (PROPOSED).
8. **`DIGEST` is `untrusted_data`.** §9 calls tool results "server data, never instructions"; they hold AI and person text (ideas, summaries, questions, findings, suggestions), so the block is untrusted data and its strings are sanitized, while the server's own facts (mode, objective, settings, limits, locale) are `server_data`.
9. **The approval-record change is in the build.** H-029 now serves the investigator with tool calls and lists both planner models (H-063 confirmed the change; H-061: live only after each slice's independent review). Nothing in this slice calls it outside tests: no handler, job or route makes a planner turn before A6 and A7, and `GEMINUS_INVESTIGATIONS` is not read yet. Offering Muse Wonder to people still needs `INVESTIGATION_PLANNER_MODELS` (A7) and the web flag (A8), after a recorded pass (A9).
10. **The eval's results are synthetic.** "A simulated tool environment from recorded fixtures": the cases' results are hand-written synthetic observations on the electronics template, each checked against `investigator.schema.json`'s `ToolObservation` when handed out; none comes from a live run. The live suite's pass bar is computed from what is measured; its finish-reason rubric against Muse Spark's is `NOT_COMPUTED` (A9 compares two reports).
11. **Tests first, where the slice allowed.** The approval record, the API availability and the fake's planner turns had their tests written and run red first (§3). The provider's planner turn and the context builder were written with their tests; mutation probes (§3) show each guarded rule fails its test when removed.

## 6. Risks

- **Meta's multi-turn and `tool_choice` behaviour is unobserved.** The replay shape (P1) and `tool_choice` any (P2) are documented, not seen live; digest is the default, and a refused `tool_choice` would be a typed `request_rejected` on A9's first turn.
- **The projections are looser than the schemas.** The model is not told the bounds and patterns in the schema (the descriptions say the important ones: one paragraph, 2000 and 500 characters); a call over a bound is an invalid turn (`invalid_arguments`), which counts towards `invalid_answer`.
- **The approval record serves a role nothing calls yet.** Until A6 and A7 it is reachable only from tests and the live eval command; a reviewer should still treat the record change as live code (H-061: live only after each slice's review).
- **Prompt growth.** Each digest step adds up to 8 KiB; at 14 steps the planner's prompt is near 180 KiB, about USD 0.16 (Muse Spark) and USD 0.56 (Muse Wonder) reserved per turn at the bound (H-061 §12), inside the USD 2.50 ceiling only if few turns fail.
- **The deployment's spend ledger does not take an investigation yet.** `internal/storage/aispend` attributes a reservation to `ai_proposal`, `ai_analysis` or `import` only, so a metered planner turn in the worker would be refused (`spend_unavailable`, nothing sent) until A3 adds the investigation target and its ceiling (A3's file list). The live eval meters with its own in-memory cap, so it is not affected.
- **The eval environment is a stand-in.** Its refusal codes follow §7, but the real executor (A7) decides them; a difference shows only in A9's closed loop.
- **Merge contention**: `internal/ai/provider` (E-slices), `internal/config/aiapproval` (any approval change), `scripts/check-architecture/rules.go` (A1, A6), `Makefile`, `docs/AI_SPEC.md`.
