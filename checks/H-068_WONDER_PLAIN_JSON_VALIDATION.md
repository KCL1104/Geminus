# H-068 validation report: Muse Wonder 1.0 answers in plain JSON

**Date: 2026-11-01 | Status: agent self-check; no independent review yet; no live call | Decision: H-068 (the coordinator's engineering decision within H-065, `docs/DECISIONS_AND_TBD.md`), building on H-049 (model choice), H-051 (Muse Wonder hidden), H-057 (one repair) and H-065 (Muse Wonder's budgets) | Requirements: REQ-008 (AI proposals) | Base: `88c9191`**

## 1. What changed

Before: every proposal request to Meta, on either model, sent `output_config.format` `json_schema` with the projection of `proposal-output.schema.json`, in which each JSON Patch value (`add`, `replace`, `test`) is a string holding the value's JSON text (`structured.EncodedDescription`). Live (H-065's tests), Muse Wonder 1.0 wrote those strings badly (`fct_tester` without its JSON quotes, `rru_loopsber},{` for a number), so all four live Muse Wonder proposals were invalid at `/changes/N/value`, their repairs too. The coordinator's probe of the same scenario request without `output_config` got clean JSON with native values in 8 s.

## 5. PROPOSED

- P1: record which answer format a call used in its provider metadata (for example `answer_format: "plainjson-0.1.0"` beside `prompt_template_version`), so an audit can tell a Muse Wonder call's instruction version apart; today it is only in the request (pinned by the goldens). A metadata field is a contract decision, not taken here.
- P2: the native schema is the projection, so it omits the bounds the structured-output subset cannot take (`minItems` of `changes`, lengths, patterns). Muse Wonder's request has no such limit; telling it the canonical bounds might cut refusals such as an empty patch (H-054). Not done: the task asks for the same projection, and the server enforces the bounds either way.
- P3: if live Muse Wonder still writes a JSON text in a string, the adapter refuses it at its place and H-057's repair names the place; if it often writes a code fence, consider a sharper instruction, never a lenient reader.

## 6. Risks

- R1: nothing at the provider constrains Muse Wonder's answer any more; every shape rule is the server's (the same strict checks as before), so a malformed answer costs a full Muse Wonder call (up to 128,000 output tokens) and at most one repair, within the unchanged spend caps (USD 40 a day).
- R2: a string at a patch value that is exactly a JSON string, array or object text (`"[1,2]"`, `"{}"`) is refused although a free-text name or domain attribute could in principle hold it; judged far less likely than the projection habit it catches, and repairable. A string that holds a number, `true`, `false` or `null` is accepted as a string and left to the review's IR check.
- R3: a research answer is the last text block after the last search step; if Muse Wonder writes narration after its JSON, the answer is refused at the root (as for Muse Spark today).
- R4: merge: `messagesOf`, `messagesBody` and `countBody` now take the cached `projected` instead of the schema, and the request structs' `OutputConfig` is a pointer; the Eino refactor (E3/E5, other branches) moves orchestration, not this code, but a branch touching these functions conflicts here.
- R5: the instruction and the native schema add about 4.9 KB to every Muse Wonder proposal request's system text (about the size of the projected schema it replaces in `output_config`); quoted and reserved accordingly.
