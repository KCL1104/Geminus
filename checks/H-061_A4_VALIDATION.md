## 5. Deviations from the design, and why

1. **The membership carries the scope** (`tenant.Membership.ActingFor`) rather than each service reading `app.investigation_id` back: `Run` sets both from the same value in the same statement, so they cannot differ, and a person's request makes no extra round trip. `internal/tenant` is outside A4's file list; the change is one field.
2. **The approval's revalidation moved into `effect`** (`Recheck`, `Check`, `ScenarioName`, `NewScenario`): "shared with approval" needs one copy. The approval keeps its own `recheck`, `scenarioName`, error types and messages as thin wrappers, so its tests and answers are unchanged.
3. **Refusal codes the design leaves open, chosen here**: an applied proposal saved or written again is `PROPOSAL_NOT_READY` (the AI's own action, not a person's decision); a proposal of another investigation, of a person, of another organization or of none is `NOT_IN_INVESTIGATION`; the tool of the other mode is `MODE_MISMATCH` at `""`; `DRAFT_CHANGED` points at `""` (the draft is not an argument); the others at `/proposal_id`. A risk that changed since the review is `RECHECK_FAILED` too. No refusal names an issue code: the contract's `ToolError` is `{code, path}` only (review round 1, §9). Not running, a demoted requester, missing dataset storage and a snapshot that cannot be read are errors (`effect.ErrEnded`, `tenant.ErrForbidden`, `effect.ErrDatasetsUnavailable`, `datasets.ReadError`), not refusals: the executor (A7) ends the investigation or records `SERVICE_UNAVAILABLE` / `DATASET_STORAGE_FAILED`.
4. **Approve and Reject answer `applied` with 409 `LIFECYCLE_CONFLICT`**, as they already did for any state other than ready (and needs_input for Reject), rather than `PROPOSAL_ALREADY_DECIDED`: `applied` is not a person's decision. The case is now explicit, tested, and written into the OpenAPI text.
5. **The planner's provider is derived**: `twin.investigations` stores the planner model, not the backend that answered, so `made_by_ai.generated_by` names `meta` for both planner models (H-060: Meta's Muse models). Under the fake provider (tests, the e2e build) the label still names Meta's model.
6. **The AI's draft write uses `patch.AIEdit`**, the proposal's own patch profile, where a person's patchDraft uses `patch.ManualDraft`; the IR is computed from the base version's stored IR (the draft is checked to hold exactly that content first) and must hash to the rechecked candidate.
7. **`LockDraft` is now `FOR UPDATE OF d`**: the draft is read with a LEFT JOIN to its AI edit's proposal, which `FOR UPDATE` alone would try to lock too (the nullable side of an outer join). The rows locked are the same as before.
8. **Test order, as it happened**: the audit catalogue's `proposal.apply` entry and its shape tests came first and ran red (§3) until the effect wrote it; the store, service and effect code was written before the effect package's tests, so those have no red run of their own (the mutation checks of §2 stand in for one); `TestMembershipNamesTheInvestigation` and `TestMarkAI` were written after their code. The behaviour-preserving extraction is held by the existing tests, which ran unchanged.
9. **A file outside A4's list**: `scripts/check-architecture/rules.go`, for the merge fix of §1 (one list name); and `internal/tenant` (deviation 1).
