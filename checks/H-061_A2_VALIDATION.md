## 5. Deviations from the design, and why

1. **The five new audit actions are not in the catalogue yet.** The slice lists `investigation.create`, `investigation.stop`, `investigation.tool_call` and `investigation.end` (and §10 `proposal.apply`). `internal/audit`'s `TestTheCatalogueMatchesTheCode` fails for an action that no production file writes, and their writers arrive with A4 (`proposal.apply`), A6 (`investigation.end`) and A7 (the other three). Adding them now would need that assertion weakened, so each lands with its writer; `actionLiteral` already scans `investigation.*`, so a writer without its entry fails the same test. The shapes the writer slices should add (all IDs, counts, flags, codes and closed lists; never text):
   - `investigation.create` (user, target `investigation`): `model_id` (mdl), `base_version_id` (mv), `mode` (edit, scenario), `source` (request, analysis), `source_analysis_id` (ana), `output_locale`, `research` (flag), `requested_model` and `planner_model` (muse-spark-1.3, muse-wonder-1.0), `replications` (count), `baseline_reused` (flag).
   - `investigation.stop` (user, target `investigation`): `reason` (stopped_by_person), `steps` (count), `by_owner` (flag: the stopper is an owner, not the requester).
   - `investigation.tool_call` (user, the requester, target `investigation`): `seq` (count), `tool` (the seven names), `outcome` (done, refused, failed), `code` (an `InvestigationToolCode`), and the AI mark `investigation_id` + `by_ai` (§11's guard requires it on every user event under the setting).
   - `investigation.end` (worker, target `investigation`): `reason` (the nine `InvestigationReason` values), `steps`, `planner_turns` (counts).
   - `proposal.apply` (user, target `ai_proposal`): `mode`, `model_id`, `base_version_id`, `patch_hash`, `server_risk_level`, `risk_level`, `scenario_id` (scn) or `draft_revision` (count), and the AI mark.
2. **`ProposalObservation.status` has a fifth value, `decided`.** §7 lists ready, needs_input, invalid and failed; but a person may approve, reject or conflict a ready proposal before the worker's next poll sees it, and without a value for that the worker would have to show the model a status that is no longer true. `save_scenario` and `write_to_draft` then answer `PROPOSAL_DECIDED` as §7 says.
3. **`ExplanationObservation.omitted`** counts the findings and suggestions the worker leaves out to keep a result within 6 KiB, so nothing is dropped silently.
4. **Shapes the design leaves open, chosen here** (A7/A8 implement them): the closing line is `{key, candidate_index, metric_path, absolute_delta, relative_delta, compared, draft_revision}` with `key` one of improved, no_improvement, not_compared, draft_written, draft_not_written; the response objective is `{metric_path, better: lower|higher}` (the request's is `{metric_path}`); a candidate's `source` is `idea` or `suggestion` and its `idea` is the call's argument; `createInvestigation` answers 202 with `InvestigationAccepted` {investigation_id, status running}, like the other queued creations (`ProposalAccepted`, `AnalysisAccepted`); entry B requires `output_locale` (as H-056 §7 wrote it). The detail codes of the operation-specific errors: `INVESTIGATION_PLANNER_NOT_OFFERED` (422 /planner_model), `INVESTIGATION_RESEARCH_OVER_CEILING` (422 /research), `INVESTIGATION_RUNNING` (409), `INVESTIGATION_DAILY_LIMIT` (429), `INVESTIGATIONS_OFF` (503 SERVICE_UNAVAILABLE), `AI_ROLE_NOT_APPROVED` (503 AI_POLICY_NOT_APPROVED). Paths use the file's `{id}` convention (`/v1/models/{id}/investigations`, `/v1/investigations/{id}`, `/v1/investigations/{id}/stop`), not H-056's `{modelId}`/`{investigationId}`.
5. **"No control characters" is read literally**: the AI text pattern refuses all of Unicode's Cc, so a tab or a line break in an idea or a question is `INVALID_ARGUMENTS` (the step becomes `invalid_call`). A5's tool descriptions should ask for one paragraph. Format characters (Cf, the bidirectional marks) are not control characters and are taken; the page shows AI text through `visible()` and `<bdi>`.
6. **Decoder-only refusals**: NFC (no schema can say it) and an integer written `1.0` (2020-12 counts it as an integer; Go's strict decoding does not, and the decoder refuses rather than rounds). Each is tested to be one the schema itself takes, so the decoder is only ever stricter than the schema.
7. **An architecture-rule change in A1's file**: `golang.org/x/text/unicode/norm` and `golang.org/x/text/transform` join the AI packages' third-party list for the NFC check (`rules.go`, `check_test.go`). A1 edits the same file; the change is two lines and a list.
8. **Go public shapes**: only `scenarios.Scenario` gained its label member (with `proposals.MadeByAI`), because a parity test holds that type to the schema member for member. `Run`, `Proposal`, `AnalysisRecord`, `Draft` and `ModelVersion` have no such test; A4 adds their members when the store layers read the label columns.
9. **The web**: §18 puts the UI in A8, but `applied` in the proposal status enum breaks the exhaustive tone map and the typed catalog keys of the proposals list and the proposal page, so this slice adds the tone and two strings in English and zh-Hant. Nothing else in the UI changed.

### R1.3 What I did not do, and why (partly disputed)

- **Six request negatives still expect `""`** (scenario without run settings, edit with run settings, `caps`, `expected_step`, both entries, entry B without its locale; also the new empty body and the stop body). Each is now a failure of the body object, not of a member value: a missing member (`required`) or a member not allowed (`additionalProperties`) is reported at its object by both validators, and `DecodeJSON` sends it that way, with the member named in the reason. So `""` is their exact path, and it is now their only path: the issues from the other entry are gone. `TestRequestNegativesNameTheirMember` pins each one's exact reason (for example `members not allowed: caps`), so each negative shows which member it fails at. The two horizon negatives did get a more exact path (`/run_config/horizon/value`).
- **Edit mode's members are not refused at `/run_config` itself.** I tried `then: {properties: {run_config: false, …}}`: the Go validator reports `/run_config` (as `false schema`), but the reference Python validator (jsonschema 4.26.0) drops the path of a `false` subschema (`Validator.descend` returns the error before it sets the path) and reports `""`, so `make spec-contracts` could not hold an exact path. A closed member list gives the same message in both and the same convention as an unknown member. No change to `internal/model/validate` was needed (a `false schema` message change was tried and reverted).
- **The nullable-union noise elsewhere** (`/from_suggestion` `got object, want null` beside `/from_suggestion/index`, and the same on a few response negatives) comes from `anyOf [X, null]`, used across the repository. It is not a request body that `DecodeJSON` answers with, and the tool decoder already reports the nearest declared member, so it stays as it is.
