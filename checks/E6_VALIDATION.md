## 3. Findings and decisions taken in the slice

1. **`handler.Reraised`: E2's contract kept (PROPOSED for review).** It merged first, and keeping it changes one test file of the two (E3's), where E3's contract changes three (E2's worker test, `internal/analyses/analyzer/worker_internal_test.go`, which reads `PanicStack()` as a string, and `internal/aigraph/analysis`'s `graph_test.go`, which compares it with the `Stack` field). The two contracts differ only for a Reraised with a value and no stack, which neither graph raises (`analysis.guard` and the proposal graph's recovery always take `runtime.Stack`). E3's row's expectation is the one expectation of a test that changed for E6; it is changed because the two slices' tests contradict each other there and cannot both hold.
2. **`repair.Plan` and E5's `Settle` kept.** `Plan` and `Prepare` were the same function body; `Settle` sets `rec.Call` and tells `answered` once, so the photo path (E5's parity test against the pipeline before E5, `onceBefore`) is unchanged, and the proposal graph, which already set them in `generate_2`, passes `nil` and gets the same record (E3's and E4's tests, among them `TestTheRepairIsMeteredAsADirectRepair`, pass unchanged).
3. **The leftover: `repair.Once`, kept and sealed.** A scan of every function and method in the touched packages that no non-test code names (comments stripped) found one: `repair.Once`. After E3 and E5 no production code calls it, but H-057's tests (`internal/ai/repair`), E4's reference (`internal/aigraph/proposal/repair_test.go`, another package, so it cannot move to a test file) and E5's parity tests hold the graphs to it, and existing tests stay unchanged. So the seal lets its one direct call pass and refuses any non-test use of it. No other leftover of the old orchestrations was found; E3, E2 and E5 deleted theirs.
4. **`Turn` sealed too.** The design names the three `LLMProvider` role methods; H-060 added the client's tool turn (`provider.Client.Turn`), which E5's package check already refuses for the photo graph. Only `einomodel` (its `Call.Turn` path) and `provider` (the backend's turn) name it today.
5. **`ModelRetryConfig` and `ModelFailoverConfig` sealed too** (H-061 §5.3 names them for E6's seal; design §6.3 says they are never set).
6. **Exact directories.** `internal/ai/provider` means that package, not the adapters or the fake beneath it (none of them names a role method; a planted call in `internal/ai/provider/meta` is refused).
7. **Names, not types.** The check is syntax only: a field or method called `Turn` on another type, in non-test code outside the two directories, would be refused (none exists), and a call by reflection or through a function variable assigned in an allowed package would not be seen. A shadowing local variable named `repair` in a file that imports the repair package would be read as the package (a false refusal, never a missed one).
8. **The seal's location**: `internal/aigraph/seal_test.go` as the slice list names it, a package with only a test file. `make architecture-check` reads it (107 packages, one more than before) and passes; `go build ./...` and `go vet` accept it.
9. **E3's and E5's package checks kept** (`internal/proposals/generator` `TestTextProposalsRunOnTheGraphOnly`, `internal/aigraph/photo` `TestNoCallAroundTheMeteredChatModel`): E5 proposed dropping its own once E6 holds the whole module, but no existing test is removed here.
10. **The panic guards stay per graph.** E2 proposed sharing `guard`, `stack` and `Panic` in E6. The analysis and proposal graphs' `Panic` types differ in what `String` prints (the type only, or the value and the stack), and each is pinned by its tests, so a shared type would change one of them: PROPOSED, not done.
11. **No `checks/H-059_VALIDATION.md`.** The live smoke runs after a deploy, and this task makes no live call and no deploy. Its plan is §6 here; the report it names is written when it runs (PROPOSED).

## 9. Risks

- The seal reads names, not types (finding 7): a new type with a field or method called `Turn` outside the two directories fails it (loudly; rename it or widen the rule in review), and a model call by reflection would pass it. The import rules (`eino-fenced`, `aigraph-has-no-storage`, `aigraph-only-in-the-worker`) and the graphs' own tests remain the other guards.
- `repair.Once` stays in production code with no production caller. The seal refuses any non-test use of it; if the reference tests move to a copy (as E5's `onceBefore` is), it can be deleted.
- The two unified contracts (§2) were each reviewed in one slice only, against that slice's tests; the merge's resolution is not reviewed yet. Both graphs' panics always carry a stack, so the `Reraised` difference cannot appear in production; the repair's `Settle` now sets the record's call a second time in the proposal graph, to the same metadata.
- The seal runs `go list ./...` from the test: a machine without `go` on `PATH` cannot run `internal/aigraph`'s tests (as `scripts/check-architecture`'s and `cmd/worker`'s tests already need it).
- `scripts/check-architecture`'s tests took 680.6 s and 765.5 s in `make backend-test` here (other agents loaded the machine), over Go's 10-minute default; the target sets 30 minutes, so only a run without `-timeout` would stop it.
