== The CLI's source at v1.37.0 (raw files of the tag) ==

- internal/cli/login.go: with --no-input and --domain alone, a user (device code) login on that
  tenant's audience (ensureAuth0URL: only an auth0.com domain); in agent mode it prints one JSON
  object {"verification_uri", "user_code", "expires_in", "interval"} on stdout, waits, then prints
  {"logged_in": true, "tenant", "domain", "expires_at"}; the access token is stored in the keyring,
  or, when that fails, in the config file (tenant.AccessToken).
- internal/auth/auth.go: the device code comes from Auth0's own CLI application
  (auth0.auth0.com/oauth/device/code); State.VerificationURI is `verification_uri_complete`;
  RequiredScopes include create/read/update:clients, create/read/update:resource_servers,
  create/read/update:users, read/update:connections, read/update:connections_options,
  read:client_keys.
- internal/config/config.go: the config file is $HOME/.config/auth0/config.json (0600, directory
  0700). internal/config/tenant.go: the token is read from the keyring, then from the config file.
- internal/keyring/keyring.go, internal/cli/logout.go: `auth0 logout <tenant>` removes the tenant from
  the config, then deletes its keyring entries; a keyring error other than "not found" fails the
  command after the config was rewritten (hence the step checks `auth0 tenants list` afterwards).
- internal/cli/tenants.go, internal/display/tenants.go: `tenants list --json` prints
  [{"name": <domain>, "active": bool}] from the config file (no authentication needed).
- internal/cli/root.go: `--agent-mode` (or AUTH0_AGENT_MODE=true) forces agent mode: JSON on stdout,
  no prompts, no colors, stderr only a JSON error envelope {"error": {"code", "reason", "message",
  "status", "details"}}, exit 0, 130 when interrupted, 1 otherwise; `--tenant` is a persistent flag.
- internal/analytics/analytics.go: events go to heapanalytics.com with the tenant among their
  properties unless AUTH0_CLI_ANALYTICS=false.
- internal/cli/data_json.go: `--data @-` (or `-`) reads the JSON payload from stdin (iostream
  PipedInput); the payload is validated against the Management API's OpenAPI document when it can be
  loaded, then sent as is (runJSONWrite).
- internal/cli/api.go: `auth0 api` takes --data inline, @file or @-, prints the response unmasked.
- internal/cli/apis.go, internal/display/apis.go: `apis list --number N` (1-1000), `apis show <id or
  audience>`, `apis create --data`, `apis update <id> --data` (PATCH /resource-servers/{id}); the JSON
  is the management.ResourceServer (go-auth0 v1.50.0 management/resource_server.go: identifier,
  signing_alg, signing_secret, token_lifetime, allow_offline_access, token_dialect,
  skip_consent_for_verifiable_first_party_clients).
- internal/cli/apps.go, internal/display/apps.go: `apps list --number N`, `apps show <id>
  [--reveal-secrets]`, `apps create --data`, `apps update <id> --data` (PATCH /clients/{id}); without
  --reveal-secrets client_secret and signing_keys are removed from the JSON (safeRaw); the JSON is the
  management.Client (go-auth0 management/client.go: client_id, name, app_type, oidc_conformant,
  callbacks, allowed_logout_urls, web_origins, allowed_origins, grant_types,
  token_endpoint_auth_method, jwt_configuration.alg, refresh_token {rotation_type, expiration_type,
  leeway, token_lifetime, infinite_token_lifetime, idle_token_lifetime,
  infinite_idle_token_lifetime}).
- internal/cli/connections.go, internal/display/connections.go: `connections list`, `connections show
  <id>` (the raw GET /connections/{id}), `connections update <id> --data` ("the entire 'options'
  object is overridden on update"), `connections enabled-clients show <id>` and `update <id> --data
  '[{"client_id", "status"}]'` (PATCH /connections/{id}/clients).
- internal/cli/users.go, internal/display/users.go: `users search-by-email <email>` (a JSON list of
  management.User), `users show <id>`, `users create --data`, `users update <id> --data`.
- go-auth0 v1.50.0 management/connection.go: ConnectionOptions.DisableSignup `disable_signup`,
  CustomScripts `customScripts`, Configuration `configuration`, ConnectionEnabledClient {client_id,
  status}.
