- 逐條紅／綠與 mutation 輸出在 `checks/evidence/2026-10-15-review/`。

## T-004 validator／patch

**HIGH：首批並行請求會讓 process 崩潰。**
- 原因：多個 goroutine 共用同一個 `jsonschema.Compiler`，且沒有鎖。
- 重現：舊碼 5 次跑 4 次 `fatal error: concurrent map writes`，`-race` 回報 189 個 race。
- 原有的並行測試先序列跑一次暖了 cache，所以看不到這個問題。
- 修正：compile 加 mutex；新增獨立 test binary 的冷啟動測試（`internal/model/validate/coldstart`），涵蓋合法與不合法輸入。
- 修後 20/20 通過，race 乾淨。

**其他 CONFIRMED（皆已修）：**
- exponential mean 為 `1e-400` 時，schema 以精確十進位判斷 >0，但 Go 解碼為 0。結果 interarrival 為 0、零時間 cycle 也被當成合法（D-033）。現在一律拒絕，`Bindings` 也把它視為零時間。
- issue 排序有兩個問題（D-023）：`Atoi` 相減會溢位，`"1"`、`"01"`、`"+1"` 也被視為相同。現在是全序：只有 RFC 6901 index 形式以長度加 bytes 比較，最後再以 severity 定序。
- metadata 16 KiB 上限原本量 raw bytes，結果受空白影響。現在量 canonical 形式。
- `Mode(3)` 會 panic，現在回 error。

**plausible 也已修：**
- patch 文件在 parse 前先檢查 2 MiB 上限。
- 整個非空 catalog 陣列的 replace／remove 一律拒絕（D-020 的 fail-closed 解讀）。
- D-022：刪除後又加回同一 id 時，不得刪除它的座標。
- D-021：scenario 不得引入 base 沒有綁定的 `samples_ref`。

**原報告更正：**
- 「`-race` 含並行測試」不足以證明安全（原測試先暖 cache）。
- 「FuzzIR：結果決定性且已排序」在上述排序缺陷下不成立。
- 「Mutation 7/7」沒有留存 log，以本次 31 個有 log 的 Go mutants 取代。
- TEST-003 的 `copy` 原本只靠 schema 拒絕、沒有測試，已補 `TestCopyIsRejected`。
- 實作解讀漏列「metric／constraint 引用只檢查存在、不檢查 node 類型」，已補列。

## T-005 hashing／dataset binding

**CONFIRMED（皆已修）：**

- Store 未正確 scope 時，hash 不符與超過大小上限的訊息會洩漏他租戶物件的 SHA-256 與大小。現在訊息不含任何值。
- 重複的超長 `logical_ref` 會產生超過 2000 字元的 message，違反 ValidationIssue schema。現在所有 issue 經 `model.NewIssue` 建立：保證有效 UTF-8、message ≤2000 字元、path ≤2048 字元（超過時縮成祖先 pointer）。

**plausible 也已修：**

**未修：**

- Store scope 失效時，知道他租戶 dataset version ULID 的人，仍可從「hash 不符」與「找不到」的差異推知該 ID 存在（不含內容或 hash）。Store 的 tenant scope 仍是主要防線，已記入 TWIN_IR_SPEC §5.2。

**原報告更正：**

## T-006 migrations／postgres

**CONFIRMED（皆已修）：**
- fn 呼叫 `runtime.Goexit`（例如在 fn 內 `t.FailNow`）時，`Tx` 不 rollback，連線外洩，`pool.Close` 卡死。
- `Classify` 丟掉呼叫端自己的錯誤鏈，repository 無法經 `Tx` 回傳 typed 409。現在 `errors.Is` 找得到呼叫端的 sentinel，`Error()` 仍不含 server 文字。
- approved proposal 的決策紀錄（decided_by、decided_at、new_version_id）與 review payload（validation、expected_effects、questions）仍可改寫。現在的規則：
  - proposal 離開 generating 後，review payload 不可改。
  - 已決策或已結束的 proposal 整列不可改。
  - 決策欄位只能在決策 transition 寫入；decided_by 必須等於 `app.user_id`；decided_at 由 DB 設為 `now()`。
  - approved 必須指向 `source_proposal_id` 指回此 proposal 的 version 或 scenario。
  - rejected 也必須有 decided_by。

**plausible 也已修：**
- object key 前綴之後只允許 server 產生的 ASCII 段。拒絕 `.` 段、以 `.` 開頭的段、空段與結尾 `/`、`%`、Unicode 相似字元與格式字元。
- audit 的 user actor 必須是 `app.user_id`。
- COMMIT 結果不明（連線在送出後中斷）時回 `ErrOutcomeUnknown`。
- 0002 down migration 撤回 schema 與 domain 的 USAGE。

**未修（設計限制）：**
- 同一 organization 內可以跨 project 引用，例如 binding 指向另一個 project 的 dataset、baseline run 屬於另一個 model。P0 的授權單位是 organization membership（D-008），project 不是隔離邊界，所以這不是越權。語意正確性由 T-012（Model service）與 T-029（baseline comparison）的 handler 檢查。
- twin_owner 可以 `DISABLE TRIGGER`，這是 table owner 的固有權限。twin_owner 只用於 migration；runtime login 不可能成為 owner，由 CheckRuntimeRole 檢查。

**原報告更正：**
- 「Tx rolls back on error/panic/cancel」原本漏了 Goexit。
- 「拒 traversal／empty segment」原本只擋字面 `..` 與內部 `//`。
- 現在兩者皆已成立。

## T-007 RLS／runtime roles／pool

**CONFIRMED（皆已修）：**
- `CheckRuntimeRole` 原本只看 `current_user`。以下 login 都能通過：
  - 以 `options=-c role=twin_api` 連線的 superuser；
  - 只能 `SET ROLE` 到 superuser 或 BYPASSRLS 角色的 login；
  - 有 REPLICATION 的 login；
  - 屬於 `pg_write_all_data` 或 `pg_execute_server_program` 的 login；
  - 擁有 trigger function 的 login。

  現在以 `session_user` 檢查，並拒絕以下任何一種：
  - 以其他角色執行；
  - 有 REPLICATION；
  - 除目標 runtime role 外屬於任何其他角色；
  - 有直接授予 login 的權限；
  - 擁有任何物件（以 `pg_shdepend` 判斷）；
  - 能在任何 schema 或 database 建立物件（涵蓋從 PG14 升級、PUBLIC 仍可在 public 建物件的 cluster）。
- worker 可以把已 COMMITTED 的 import 改回 FAILED。
- worker 可以 reject 或改寫一個等待人類審核的 proposal。
- `Guard` 漏掉 session-level 的 `app.oidc_subject`、WITH HOLD cursor 與 temp table。現在檢查：
  - migrations 讀取的所有 `app.*` 設定（有測試綁定這份清單）；
  - 任何 session-level SET；
  - cursor、temp table、advisory lock、LISTEN。
- twin 的 function 沒有固定 search_path，可被 public schema 的同名函式 shadow。現在全部固定為 `pg_catalog, pg_temp`。

**plausible 也已修：**
- worker 偽造 user audit。
- D-037 改由 trigger 強制：即使 worker 被誤授較大的 UPDATE，也不能改 mapping、links 或身分欄位。

**未修：**
- `cmd/` 目前還沒有呼叫 Guard 與 CheckRuntimeRole。**T-013（API 組裝）與 T-019／T-023（worker）必須在啟動時呼叫 CheckRuntimeRole，並為 pool 設定 Guard**，已記入兩者的移交事項。

**原報告更正：** D-008 已批准；API_DATABASE §10 改為記錄實際執行過的 PostgreSQL 測試。
